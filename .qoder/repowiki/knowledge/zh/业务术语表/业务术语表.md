### JSAPI 支付
- 定义：本项目对接的微信支付交易类型（trade_type=JSAPI），即微信公众号网页与小程序场景的支付。特征是必须传入 `payer.openid`，下单返回 `prepay_id` 后由前端用 JS-SDK（`wx.requestPayment` 或微信内 H5 的 `WeixinJSBridge.invoke`）调起，不是微信支付产品里的「H5 支付（MWEB）」。
- 别名：JSAPI、jsapi、微信内 H5 支付

### H5 支付（MWEB）
- 定义：微信支付产品线中专指「手机浏览器（非微信内）支付」的交易类型（trade_type=MWEB），下单返回 `h5_url`，前端 302 跳转唤起微信。本项目虽在 Gateway 常量中声明了 `TradeTypeH5`，但抽象层 `PrepayResult` 没有 `h5_url` 字段，mock 也落入 default 分支返回 JSAPI 的 `InvokeParams`，因此当前不可用，属于预留但未实现的模式。
- 别名：H5 支付、MWEB、微信外 H5 支付

### NATIVE 支付
- 定义：微信扫码支付（trade_type=NATIVE），商户展示二维码让用户扫码完成支付。mock 渠道能返回 `CodeURL`（形如 `weixin://wxpay/bizpayurl?mock=...`），但真实接入方案尚未在 doc.go 中编写，且 service 层无特殊处理。
- 别名：NATIVE、扫码支付、Native 支付

### APP 支付
- 定义：trade_type=APP 的原生 App 支付，返回给原生 SDK 的参数名是下划线风格（partnerid/prepayid/sign），与 JSAPI 的驼峰 `InvokeParams` 不同。本项目仅声明常量，mock 走 default 分支返回 JSAPI 参数，故当前不可用。
- 别名：APP、App 支付

### Gateway 接口
- 定义：本项目支付渠道抽象层的统一接口，定义 `Code / Prepay / QueryOrder / CloseOrder / ParseNotify / Refund` 六个方法，将具体支付渠道的差异收敛在此之后。service 层只依赖此接口，新增渠道只需实现该接口并在 registry 注册，无需改动上层。
- 别名：channel.Gateway、渠道网关、支付渠道抽象

### Mock 渠道
- 定义：内置的仿真支付渠道，纯内存实现，用于本地端到端跑通「下单 → 预支付 → 回调 → 查单」全流程而不真正扣款。仅在 `server.mode=debug` 下注册；release 模式下刻意禁用，避免产生不会到账却被视为成功的脏数据。
- 别名：mock、仿真渠道、模拟渠道

### 回调验签
- 定义：收到微信支付异步通知后，使用 APIv3 密钥对请求头中的 `Wechatpay-Signature` / `Wechatpay-Timestamp` / `Wechatpay-Nonce` / `Wechatpay-Serial` 进行 RSA 验签，并用 APIv3 密钥对密文报文做 AES-256-GCM 解密。这是安全边界，校验失败不得交给业务层；mock 渠道跳过此步骤仅供联调。
- 别名：验签、回调签名验证、ParseNotify 验签

### 证书模式 / 公钥模式
- 定义：微信支付回调验签的两种凭据模式，二选一：证书模式需要定期下载并轮换平台证书（老商户号常用），公钥模式使用固定不变的微信支付公钥（2024 年后新申请商户号的默认方式）。`config.WechatPayConfig.Validate()` 要求两套字段至少配齐一套。
- 别名：证书模式、公钥模式、API 证书模式、微信支付公钥模式

### 订单状态机
- 定义：领域模型中固化的订单与支付流水流转规则：Order 为 `CREATED → PAYING → PAID`（可转 CLOSED / REFUNDED），Payment 为 `INIT → PREPAID → SUCCESS`（可转 FAILED / CLOSED）。非法流转直接返回错误，service 层不直接判断状态字符串。
- 别名：状态机、Order 状态机、Payment 状态机

### draft-copy-then-swap
- 定义：内存仓储的并发写策略：读锁内拷贝一份副本，修改副本后再用写锁换回原 map 条目；对外返回的也是 `Clone()` 副本，调用方拿到的是快照。用于保证内存仓储在并发回调场景下的数据一致性。
- 别名：副本隔离、copy-on-write 仓储

### 分账 / 代金券 / 委托代扣
- 定义：微信支付的其他产品线能力，当前项目的 Gateway 接口没有对应方法，也不在已建模的业务范围内，属于未来扩展点。
- 别名：分账、代金券、委托代扣
