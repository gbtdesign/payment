模块按三层划分：
- `internal/model` 是语义中心，集中定义 Order 与 Payment 两个领域实体及其状态机（OrderStatus: CREATED→PAYING→PAID→REFUNDED/CLOSED；PaymentStatus: INIT→PREPAID→SUCCESS/FAILED/CLOSED），所有状态变更统一走 `transit` + `Mark*` 方法，禁止外部直接赋值 Status。
- `internal/service` 实现业务编排：`OrderService` 负责下单（校验金额、渠道注册、生成 out_trade_no 并落库）；`PaymentService` 负责 Prepay（调渠道下单、推进流水 PREPAID、订单 PAYING）、HandleNotify/HandlePayload（幂等回调、金额校验、并发保护）、SyncFromChannel（掉单兜底，复用 HandlePayload 保证回调与查单路径一致）。
- `internal/dto` 仅做 HTTP 请求/响应与 model 之间的转换（FromOrder / FromPrepayResult / FromPayment），金额在 API 侧用字符串「元」，内部一律以 int64「分」表示。
依赖方向单向：service → model + repository/channel/errcode/pkg；dto → model + pkg/money；model 不反向依赖 service 或 dto。service 通过接口注入 repository 与 channel.Registry，不感知 HTTP 框架与具体渠道 SDK，便于纯单元测试覆盖状态机与幂等逻辑。
