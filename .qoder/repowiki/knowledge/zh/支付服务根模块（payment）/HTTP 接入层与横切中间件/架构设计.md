模块按职责分为两个子包：
- `internal/handler`：每个业务域一个 Handler 结构体（OrderHandler、PaymentHandler、CallbackHandler），通过构造函数注入 service 依赖；公共能力集中在 `handler.go`——`bindJSON` 区分空体/语法错误/字段校验三类失败并映射到 `errcode`，`pathParam` 校验路径参数，`amountParseError` 把 `pkg/money` 的错误转成面向客户端的中文提示。
- `internal/middleware`：纯横切关注点，每个文件一个 `gin.HandlerFunc` 工厂（CORS、Logger、RequestID、Recovery），不持有业务状态，仅操作 gin.Context / Request Header / Context。

边界约定由包注释明确：handler 中不允许出现订单状态或金额等业务判断，回调接口因微信 APIv3 规范不走统一响应体而单独实现于 `callback_handler.go`；middleware 中不允许出现任何业务规则。依赖方向单向向外：handler → service/channel/dto/response/errcode，middleware → pkg/logger/pkg/idgen/pkg/response，二者互不引用。
